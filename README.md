# 📖 Software Diary

> **Learning something every day, one concept at a time.**

I have been working in software engineering for many years, but I still feel that there is always something new to learn.

There are days when I learn a new concept, understand it, use it at work, and then a few months later I realize that I have forgotten some part of it.

Sometimes I save things in a notebook.

Sometimes I bookmark a website.

Sometimes I take screenshots.

Sometimes I write something down and never look at it again. 😄

So I decided to do something simple.

I started **Software Diary**.

This is where I want to write down the things I learn during my software engineering journey.

Not just definitions.

Not just copied documentation.

I want to write things in a way that **I can understand when I come back to them later**.

And if someone else finds these notes useful, even better.

---

## 🌱 Why I Started This

I don't want this repository to be another collection of notes that I create today and forget tomorrow.

I want it to be something that grows with me.

Whenever I learn something interesting, I want to ask myself:

* What is this?
* Why do we need it?
* What problem does it solve?
* How does it actually work?
* Where would I use it?
* What are the things I should be careful about?
* Can I explain it to someone else?

If I can explain a concept in simple words, I probably understand it better.

So this diary is also a way for me to **learn by writing**.


# 📅 One Concept a Day

The main idea behind this diary is very simple:

**I don't have to learn everything in one day.**

For example:

```text
Day 1  → CAP Theorem

Day 3  → Load Balancing

Day 6  → Message Queues

```

Then continue.

Some days I may learn a completely new topic.

That's okay.

The important thing is to keep learning.

# 🔄 My Learning Process

This is how I want to approach each topic:

```text
              Find a topic
                   ↓
               Learn it
                   ↓
            Try to understand
                   ↓
              Practice it
                   ↓
              Write about it
                   ↓
           Draw / add examples
                   ↓
                Review
                   ↓
              Push to GitHub
```

And later, when I come back to the topic:

```text
             Read my old notes
                    ↓
             Find what I missed
                    ↓
              Learn more
                    ↓
             Update the notes
```

So the pages in this repository are never really "finished".

They can grow as my understanding grows.
